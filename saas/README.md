# saas — 고객망에서 도는 것

pqcaton을 서비스로 제공할 때, **고객 네트워크 안에 놓이는 부분**만 여기 있습니다.

| | 어디에 |
|---|---|
| **[`runner/`](runner/)** — 고객 서버에서 고객 권한으로 도는 코드 | **여기**(공개) |
| 컨트롤 플레인 코드·설계 · 인프라 · 운영 · 사업 | **`pqcaton-saas`**(비공개) |

## 왜 이렇게 나누나

**선은 「누가 하는 일이냐」입니다.**

러너는 고객 서버에서 그들의 권한으로 도는 코드입니다 — 무엇을 하는지 읽을 수 없으면 놓을
이유가 없습니다. 반대로 컨트롤 플레인은 우리 서버 안의 일이라 고객이 검증할 대상이 아니고,
보안 제품의 인프라 지도를 공개하는 것은 그 자체로 위험합니다.

읽을 수 없는 것을 그 자리에 두지 않는다는 원칙은
[LICENSING](../LICENSING.md#그래도-소스는-공개합니다)에 적힌 그대로입니다. 그 원칙이 적용되는
자리가 **고객망 안**입니다.

## 왜 별도 폴더인가

호스팅은 **제품이 아니라 제공 방식**입니다. `pkg/inventory`는 호스팅과 무관하게 같은 일을
하고, 고객이 자기 서버에 설치해도 그대로 돕니다.

경계는 하나입니다 — **`pkg/`는 호스팅을 모릅니다.** 여기 있는 것이 그것을 부르지, 반대는
없습니다.

**러너조차 호스팅 때문에 생긴 것입니다.** 고객이 컨트롤 플레인을 자기 환경에 두면 러너가
필요 없습니다 — `pqcota-ingest`가 관측 결과를 직접 씁니다. 이 폴더 전체가 *"우리에게 맡길
때만"* 나오는 것입니다.

## 한 줄 요약

관측은 **고객 노드에서만** 됩니다(`/proc`·JVM attach·`AF_PACKET`). 순수 SaaS가 성립하지 않으므로
**고객망 안의 러너 + 호스팅되는 컨트롤 플레인**으로 나뉩니다. 러너가 하는 일은 지금 데모의
`pqcota-ctl`과 같습니다 — 새로 만드는 것은 그것이 바깥과 이야기하는 경로뿐입니다.
