# runner — 고객망에서 도는 것

러너는 **고객 서버에서 고객의 권한으로** 도는 코드입니다. 무엇을 하는지 읽을 수 없으면 놓을
이유가 없습니다 — 그래서 이것만 공개 리포에 있습니다.

> **아직 코드가 없습니다.** 자리와 기준만 있습니다. 러너를 만들 때 여기 둡니다.

## 러너가 하는 일

지금 데모의 `pqcota-ctl`과 같습니다. 새로 붙는 것은 **바깥과 이야기하는 입** 하나뿐입니다.

```
[컨트롤 플레인]  계획 · 리뷰 · 확정 · 인벤토리 · 리포트
      │ ▲
 작업 │ │ 결과        둘 다 고객이 밖으로 연 HTTPS. 인바운드 없음
      ▼ │
[고객망]  러너 ──SSH──▶ 노드들 (collector 반입·실행·회수 / 플레이북 적용·되돌림)
```

**대상 노드에는 아무것도 설치되지 않습니다.** collector를 밀어 넣고, 실행하고, 결과를 가져온
뒤 지웁니다. 에이전트도 데몬도 남지 않습니다.

**러너는 상태를 갖지 않습니다.** 죽으면 다시 띄우면 그만이고, 데이터는 컨트롤 플레인에
있습니다. 상주하지도 않습니다 — 정해진 스케줄에 깨어나 할 일을 묻고, 하고, 끝냅니다.

## 밖으로 보내는 것과 보내지 않는 것

**이 절이 이 문서에서 가장 중요합니다.** 고객 보안팀이 먼저 볼 자리입니다.

| 보낸다 | 보내지 않는다 |
|---|---|
| 관측 결과(`CollectionResult`) — 어떤 노드가 어떤 암호 자산을 쓰는가 | **접속 정보 일체** — 주소·포트·계정·키·비밀번호. 러너 설정에만 있습니다 |
| 관측된 통신 엣지와 협상 결과 | **파일 내용** — 설정 파일 원문을 읽어 보내지 않습니다 |
| 완전성 맵 — 무엇을 관측하지 못했는가 | **패킷 페이로드** — 핸드셰이크의 협상 그룹만 봅니다. 복호화하지 않습니다 |
| 러너 상태(버전·마지막 실행) | **애플리케이션 데이터** |

**등재된 노드의 주소는 올리지 않습니다.** 컨트롤 플레인이 갖는 것은 머신 지문과 표시이름이고,
작업 지시도 식별자로만 합니다 — 우리 DB가 털려도 고객 내부 주소 지도가 나오지 않습니다.

**예외는 아직 모르는 상대입니다.** collector가 깔린 적 없는 통신 상대는 지문도 표시이름도
없어, 주소가 없으면 운영자가 판단할 근거가 하나도 없습니다. 그래서 기본값이 그것만 올립니다
(`PQCATON_EXPOSE_ADDR=unknown`). 전부 감추는 `off`와 전부 올리는 `on`도 있고, **고르는 것은
고객입니다.** 그 설정은 러너에 있어 우리가 바꿀 수 없습니다.

## 무엇이 무엇으로 막는지 — 뭉뚱그리지 않습니다

둘은 강도가 다릅니다. 같은 것처럼 적으면 약한 쪽이 실제보다 강하게 들립니다.

| 막히는 것 | 무엇이 막나 |
|---|---|
| **SSH 키·비밀번호** | **타입입니다.** pqcota의 `MachineEndpoint`에 비밀 필드가 아예 없습니다 — 인벤토리에 실리는 것은 `node_id`·이름·IP·포트뿐이라 담을 자리가 없습니다. 접속 정보는 실행에만 쓰고 영속하지 않습니다 |
| **파일 원문 · 패킷 페이로드** | **규약입니다.** `CollectionResult.raw_capture`는 자유형 `bytes`라 스키마가 막아 주지 않습니다. pqcota가 계약 주석에 *"여기에 설정 파일 원문·패킷 페이로드·자격증명을 담지 않는다"*를 명문화했고(v0.2.0), collector가 그것을 지킵니다 |

**규약은 타입보다 약합니다.** collector를 바꾸면 깨질 수 있는 약속이라 수신 API가 한 겹 더
봅니다. 고객 보안팀에는 이 차이를 그대로 말합니다 — "스키마가 막는다"고 뭉뚱그리면 나중에
한 줄이 틀린 것이 문서 전체의 신뢰를 깎습니다.

## 설치

관리창에서 받은 플레이북을 러너 노드에서 한 번 돌립니다. **대상 노드 정보는 운영자가 직접
채웁니다** — 관리창에 입력할 자리를 두지 않습니다. 주소·계정·키가 그곳을 거치면 우리가 그것을
보관하게 되기 때문입니다.

```bash
curl -O <다운로드 URL>
ansible-playbook install-pqcaton-runner.yml
```

플레이북이 러너와 collector를 배치하고 스케줄을 걸며, **템플릿이 어디에 있고 무엇을 채우고
왜 우리가 그것을 받지 않는지**를 출력과 README로 알려 줍니다.

**대상 노드에 필요한 권한은 아직 정하지 않았습니다** — 관측용(`CAP_NET_RAW`)과
적용용(파일 쓰기·서비스 재시작)을 나눌지가 열려 있습니다.

## 왜 이것만 공개인가

읽을 수 없는 것을 그 자리에 두지 않는다는 원칙은
[LICENSING](../../LICENSING.md#그래도-소스는-공개합니다)에 적힌 그대로이고, 그 원칙이 적용되는
자리가 **고객망 안**입니다.

반대로 컨트롤 플레인은 우리 서버에서 돕니다. 고객이 검증할 대상이 아니고, 보안 제품의 인프라
지도를 공개하는 것은 그 자체로 위험합니다 — 그쪽 설계와 구현은 별도 비공개 리포에 있습니다.
