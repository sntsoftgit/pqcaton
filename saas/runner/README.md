# runner: 고객망에서 실행되는 것

컨트롤 플레인이 시킨 관측을 **고객 서버에서 고객의 권한으로** 수행하는 프로그램입니다.
pqcota의 참조 플레이북으로 collector를 반입·실행·회수하고, 그 결과를 올립니다.

무엇이 공개이고 무엇이 아닌지는 [`saas/README.md`](../README.md)에 있습니다.

**이 코드가 공개인 이유는 하나입니다**. 고객 서버에서 고객 권한으로 도니, 무엇을 밖으로
보내는지 **읽어서 확인할 수 있어야** 합니다. 아래 표들이 그 확인의 기준입니다.

> **§ 표기**: 소스 주석의 `§6.3.1` 같은 번호는 컨트롤 플레인 규정서의 절이고 **그 문서는
> 비공개입니다.** 번호를 타고 갈 수 없어도 아래 표와 코드로 전부 확인됩니다. 확인의 근거는
> 문서가 아니라 코드입니다.

## 밖으로 보내는 것과 보내지 않는 것

| 보낸다 | 보내지 않는다 |
|---|---|
| 관측 결과(`CollectionResult`). 어떤 노드가 어떤 암호 자산을 쓰는가 | **접속 정보 일체**: 주소·포트·계정·키·비밀번호. 러너 설정에만 있습니다 |
| 관측된 통신 엣지와 협상 결과 | **파일 내용**: 설정 파일 원문을 읽어 보내지 않습니다 |
| 완전성 맵. 무엇을 관측하지 못했는가 | **패킷 페이로드**: 핸드셰이크의 협상 그룹만 봅니다. 복호화하지 않습니다 |
| 러너 상태(버전·마지막 실행) | **애플리케이션 데이터** |

**등재된 노드의 주소는 올리지 않습니다.** 컨트롤 플레인에 남는 것은 머신 지문과 표시이름이고,
작업 지시도 식별자로만 합니다.

연결확인 파일에는 접속 주소가 적혀 있지만(`10.20.3.14:22`), **러너가 조직 단위 키로 토큰을
만들고 원본을 버립니다.** 밖으로 나가는 구조체(`Enrollment`)에 주소 필드가 **아예 없는 것**이
그 보장입니다. 키는 러너 설정에만 있어 우리 쪽에서는 되돌릴 수 없습니다.

**예외는 아직 모르는 상대입니다.** collector가 깔린 적 없는 통신 상대는 지문도 표시이름도
없어, 주소가 없으면 운영자가 판단할 근거가 하나도 없습니다. 그래서 기본값이 그것만 올립니다
(`PQCATON_EXPOSE_ADDR=unknown`). 전부 감추는 `off`와 전부 올리는 `on`도 있고, **고르는 것은
고객입니다.** 그 설정은 러너에 있어 우리가 바꿀 수 없습니다.

**대상 노드에는 아무것도 설치되지 않습니다.** collector를 밀어 넣고, 실행하고, 결과를 가져온
뒤 지웁니다. 에이전트도 데몬도 남지 않습니다.

## 대상 노드에 쓰지 않습니다

컨트롤 플레인이 주는 작업에는 종류가 있습니다. 지금 이 러너가 실제로 하는 것은 **읽는 것
둘뿐**입니다.

| 종류 | 이 러너가 | |
|---|---|---|
| `enroll` | 붙어서 머신 지문을 확인합니다 | 읽기 |
| `observe` | collector를 반입·실행·회수합니다 | 읽기 |
| `provision` | **거절합니다.** 아직 만들지 않았습니다 | 쓰기 |
| 그 밖의 이름 | **거절합니다** | 해당 없음 |

모르는 이름을 관측 플레이북으로 돌리지 않습니다. 그것이 쓰기 작업일 때 대상 노드에 무슨
일이 날지 이 코드가 모르기 때문입니다. 나중에 새 종류가 생겨도 **옛 러너가 아무 표시 없이 엉뚱한
일을 하지 않습니다.** 적용(`provision`)을 넣을 때는 이 파일에 그 사실이 먼저 보입니다.

그대로 적혀 있고, `make check-cases` 가 표와 테스트를 맞대 어긋나면 막습니다.

컨트롤 플레인 명세(`pqcaton-saas`)에도 같은 표가 있습니다. **원본은 여기입니다.** 코드가

## 무엇이 무엇으로 막는지: 뭉뚱그리지 않습니다

둘은 강도가 다릅니다. 같은 것처럼 적으면 약한 쪽이 실제보다 강하게 들립니다.

| 막히는 것 | 무엇이 막나 |
|---|---|
| **SSH 키·비밀번호** | **타입입니다.** pqcota의 `MachineEndpoint`에 비밀 필드가 아예 없습니다. 인벤토리에 실리는 것은 `node_id`·이름·IP·포트뿐이라 담을 자리가 없습니다. 접속 정보는 실행에만 쓰고 영속하지 않습니다 |
| **파일 원문 · 패킷 페이로드** | **규약입니다.** `CollectionResult.raw_capture`는 자유형 `bytes`라 스키마가 막아 주지 않습니다. pqcota가 계약 주석에 *"여기에 설정 파일 원문·패킷 페이로드·자격증명을 담지 않는다"*를 명문화했고(v0.2.0), collector가 그것을 지킵니다 |

**규약은 타입보다 약합니다.** collector를 바꾸면 깨질 수 있는 약속이라 수신 API가 한 겹 더
봅니다. 고객 보안팀에는 이 차이를 그대로 설명합니다. "스키마가 막는다"고 뭉뚱그리면 나중에
한 줄이 틀린 것이 문서 전체의 신뢰를 떨어뜨립니다.

---

**설치 안내는 여기 없습니다.** 서비스가 줍니다. 관리창에서 받은 플레이북이 러너를 놓고,
무엇을 채워야 하는지를 출력과 README로 알려 줍니다.

**이 리포를 직접 써서 이관을 진행할 수도 있습니다.** 그때는 러너가 필요 없습니다. pqcota로
관측하고 [`pkg/inventory`](../../pkg/inventory)로 판정하면 됩니다. 러너는 **우리에게 맡길 때만**
나오는 것입니다.
