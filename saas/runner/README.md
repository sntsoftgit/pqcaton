# runner — 고객망에서 도는 것

**이 폴더만 pqcaton에 남습니다.** 컨트롤 플레인의 설계와 구현은 별도 리포(`pqcaton-saas`)로
갑니다 — [왜 나누나](../README.md#무엇이-여기-남고-무엇이-옮겨-가나).

> **아직 코드가 없습니다.** 자리와 기준만 있습니다. 러너를 만들 때 여기 둡니다.

## 왜 이것만 공개인가

러너는 **고객 서버에서 고객의 권한으로** 도는 코드입니다. 무엇을 하는지 읽을 수 없으면 놓을
이유가 없습니다. 반대로 우리 서버 안의 일은 고객이 검증할 대상이 아니고, 보안 제품의 인프라
지도를 공개하는 것은 그 자체로 위험합니다([LICENSING](../../LICENSING.md#그래도-소스는-공개합니다)).

**그 선이 이 폴더 경계입니다.**

## 무엇을 확인해야 하나

고객 보안팀이 이 코드에서 확인할 것은 넷입니다. 근거는 [러너 설계 §4](../design.md)에
있습니다 — **컨트롤 플레인 설계가 옮겨 갈 때 그 절이 이 문서로 옵니다.**

| | |
|---|---|
| **밖으로 보내는 것** | 관측 결과 · 관측된 통신 엣지 · 완전성 맵 · 러너 상태 |
| **보내지 않는 것** | 접속 정보 일체(주소·포트·계정·키·비밀번호) · 파일 원문 · 패킷 페이로드 · 애플리케이션 데이터 |
| **무엇이 막나** | SSH 키·비밀번호는 **타입**이 막고(담을 필드가 없습니다), 파일 원문·패킷 페이로드는 **규약**이 막습니다. **강도가 다릅니다** — 뭉뚱그리지 않습니다 |
| **대상 노드에 필요한 권한** | **아직 정하지 않았습니다.** 관측용과 적용용을 나눌지가 열려 있습니다 |

## 설치

관리창에서 받은 플레이북을 러너 노드에서 한 번 돌리고, **대상 노드 정보는 운영자가 직접
채웁니다** — 우리는 받을 자리를 두지 않습니다([§3](../design.md)).
