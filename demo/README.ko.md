# 데모: pqcota 위에 얹는 거버넌스

[개요](../README.ko.md) · [릴리스 노트](../RELEASE_NOTES.ko.md) · [여정](../docs/journey.ko.md) · [설계](../docs/developers.ko.md) · [검증 기준](../docs/testcases.ko.md) · **데모** · [구조 그림](../README.ko.md#한-그림으로)

📊 **실행 전 예상 결과**는 [`expected-output/`](expected-output/)에 있습니다. 확장 리포트와 거버넌스 토폴로지 샘플, 그리고 차이점 설명이 들어 있습니다.

## 이 데모가 세우는 환경

pqcota 데모를 처음 보는 사람을 위해 적습니다. **결제 서비스를 흉내 낸 3노드**가 도커로 뜨고,
그 위에서 관측이 이뤄집니다.

| 노드 | 무엇이 도나 | 왜 그렇게 두었나 |
|---|---|---|
| `web-gw` | 최신 OpenSSL 3 · 클라이언트 | 트래픽을 보내는 쪽. SSH 등급은 클라이언트가 정합니다 |
| `pay-app` | JVM(JCA provider를 런타임에 등록) | **정적 스캔으로는 안 보이고** attach로만 잡힙니다 |
| `pay-db` | 레거시 OpenSSL 1.1.1 · 서버 · 앱 둘이 한 libssl 공유 | 양자취약이 어디까지 번지는지(영향 반경) |

망은 둘로 갈라져 있습니다. `corp`(웹·앱·DB가 닿는 곳)와 `db`(격리 tier). 그래서 어떤 통신은
관측되고 어떤 통신은 원리상 안 보입니다. **그 차이가 「없다」와 「못 봤다」를 구분합니다.**

환경 자체는 pqcota의 `demo/topology/topology.yaml` 하나가 정의합니다. 그 파일을 고치면 노드와
망이 달라지고, **선언은 거기서 만들어지므로 우리 쪽은 손댈 것이 없습니다**(아래).

## 무엇을 얹나

이 데모는 **독립 스택이 아니라 확장**입니다. [pqcota의 디스커버리 데모](https://github.com/randyinthedev-hash/pqcota/tree/v0.20.0/demo)를
그대로 띄운 뒤, 그 위에 이 리포의 기능, 곧 **선언 대비 3-상태 대조(CONFIRMED/UNDECLARED/UNOBSERVED) +
리뷰 큐 + 거버넌스 토폴로지**를 얹습니다.

```
관측 등급 (pqcota)              →   + 선언 대비 reconciliation (pqcaton)
🟢 web-gw→pay-app MLKEM                🟢 web-gw→pay-app  TLS  CONFIRMED
🔴 web-gw→pay-db  고전                 🔴 web-gw→pay-db   TLS  CONFIRMED
🟢 web-gw→pay-app SSH sntrup761        🟢 web-gw→pay-app  SSH  UNDECLARED ← 선언 안 된 통신!
🔴 web-gw→pay-db  SSH curve25519       🔴 web-gw→pay-db   SSH  UNDECLARED
                                       ⚪ pay-db→pay-app  TLS  UNOBSERVED (선언했으나 미관측 ≠ 부재)
```

## 실행

이 절을 마치면 `http://127.0.0.1:8765`에서 데모 화면이 열리고, 아래 [화면을 차례로 지나기](#화면을-차례로-지나기)대로 01~04를
한 바퀴 돌 수 있습니다.

**실행하는 자리.** 이 리포와 상류 pqcota 리포 다섯 개를 한 폴더 아래에 나란히 두고, 아래 명령을 `pqcaton/demo`에서
실행합니다(받는 방법은 [빠른 시작](../README.ko.md#데모로-써-보기)에 있습니다). Docker · Go · python3과 로그인한 `gh`가
필요합니다([요구 사항](#요구-사항)). 데모의 종단 검증은 Linux x86-64에서 했고, macOS는 검증하지 않았습니다.

```bash
# 1) OSS 디스커버리 데모를 먼저 띄운다 (환경 + 수집)
../../pqcota/demo/scripts/up.sh
../../pqcota/demo/scripts/demo.sh

# 2) pqcaton의 대조·토폴로지를 그 위에 확장
./scripts/extend.sh          # 산출: demo/topology-governance.svg

# 3) (골라서) 같은 데모를 화면으로 본다. 화면은 pqcota-ctl 안에서 돌고, 이 기계의 브라우저로 연다
#    먼저 go.mod가 고정한 판의 공식 수집기를 받아 확인해 둔다(gh 로그인 필요). ui.sh는 내려받지 않는다.
#    -arch는 pqcota-ctl 컨테이너의 대상이다(보통 linux-amd64, Apple Silicon의 Docker는 linux-arm64). ui.sh가 다르면 거절한다
(cd .. && go run ./inventory/cmd/pqcaton-collectors fetch -arch linux-amd64 -out ~/.cache/pqcaton-demo/collectors-v0.20.0)
./scripts/ui.sh              # → http://127.0.0.1:8765 · 끝낼 때: ./scripts/ui.sh stop

# 4) 정리 (core 데모가 환경 소유)
../../pqcota/demo/scripts/down.sh
```

- **처음 실행은 오래 걸립니다.** `up.sh`가 노드 이미지를 빌드합니다. `extend.sh`가 「Done」으로 끝나면 데모가 준비된 것입니다.
- **3)의 fetch는 한 번이면 됩니다.** 이미 있는 폴더를 덮어쓰지 않으므로 같은 폴더로 다시 받으면 거절합니다. 준비한 폴더를
  그대로 다시 씁니다.
- **브라우저**: `ui.sh`를 실행한 기계에서 `http://127.0.0.1:8765`를 엽니다. 다른 기계에서 보려면 그 포트를 SSH로 넘깁니다
  (`ssh -L 8765:127.0.0.1:8765 '<그 기계>'`). 화면마다 무엇을 하는지는 [화면을 차례로 지나기](#화면을-차례로-지나기)에 있습니다.
- **끝내기**: `Ctrl+C`는 중계만 닫습니다(화면은 계속 돌고, `ui.sh`를 다시 실행하면 다시 열립니다). `./scripts/ui.sh stop`은
  화면을 멈추고 작업 폴더는 남깁니다. `down.sh`는 컨테이너를 지우고, 작업 폴더도 함께 사라집니다.

### 화면을 차례로 지나기

아래 순서는 `ui.sh`가 처음 연 화면에서 시작합니다. 위쪽 막대에 화면마다 상태가 보입니다.

| 화면 | 처음 상태 | 확인하거나 입력할 것 | 다음으로 넘어갈 때 |
|---|---|---|---|
| 대상 노드와 기대 상태(01 관측의 첫 구역에서 엽니다) | 관리 대상 노드 3, 「연결할 관측 이름이 없습니다」 | 입력할 것이 없습니다. 노드마다 연결된 관측 이름이 보입니다 | 바로 |
| 암호 자산 스코프(01 관측의 「규칙 고치기」로 엽니다) | 「아직 계층이 없습니다」 | 첫 바퀴에서는 건너뜁니다. 02 · 03은 상류 적재에 준 정책을 씁니다 | 바로. 정책을 바꾸는 일은 [새 정책 활성화](#새-정책-활성화)에 있습니다 |
| 01 관측 | 접근 정보 표에 노드 3대, 수집기와 `collector.jar` 줄이 모두 ✓ 「확인됨」 | **관측 시작**을 누릅니다. 1분쯤 걸립니다(네트워크 관측 구간 60초) | 「관측을 마쳤습니다. 받은 결과 파일 …개가 지금 결과가 됐습니다」가 보이면 **02 대조에서 보기** |
| 02 대조 | 판정할 항목 2개, 다시 관측해 볼 자산 1개 | 개수(CONFIRMED · UNDECLARED · UNOBSERVED)와 그 숫자가 나온 줄을 봅니다. 관측 구간 동안 오간 통신이 없는 엣지는 UNOBSERVED로 보입니다 | **판정 큐 열기** |
| 03 판정 | 결론이 빈 정책 1개(`openssl/libssl`) | **이 정책의 결론**을 적습니다. 04에서 만들 것이 있도록, 기계가 답한 항목 하나(예: `pay-db/openssl/libssl`)의 **계획에 넣기**를 켜고 **조치 종류** · **목표 알고리즘** · **위임 수준**을 고릅니다. **승인자**와 **서명**을 적고 **확정하고 계획 내보내기**를 누른 뒤, 이어지는 확인 화면에서 **확정합니다**를 누릅니다 | 「이 판정 세션은 확정되었습니다」가 보이면 04로 |
| 04 프로비저닝 | 확정한 계획과 그 조치, 승인 키 ✓ | **승인자**를 적고 「위 조치를 검토했고 승인합니다」를 켠 뒤 **승인 서명**을 누르고, 확인 화면에서 **이 내용으로 서명**을 누릅니다. 이어서 **플레이북 생성**을 누릅니다 | `plan.provision.yml` · `plan.rollback.yml`이 보이면 끝입니다. 노드에 적용하는 일은 운영자가 Ansible로 합니다 |

### 화면으로 보기

`ui.sh`는 **실제 배치와 같은 자리에** 화면을 띄웁니다. 01 관측은 화면이 떠 있는 기계에서 Ansible을 부르므로, 화면은
노드에 닿는 기계에서 돌아야 합니다. 데모에서 그 기계는 `pqcota-ctl`입니다. 운영자는 자기 기계에서 SSH 터널로 화면을
봅니다([운영자 안내서 5절](../docs/operator-guide.ko.md#5-다른-기계에서-보기)). 데모의 `pqcota-ctl`에는 SSH 서버가 없어서,
그 터널을 `docker exec` 중계가 대신합니다.

**포트를 공개하지 않습니다.** 화면에는 로그인이 없어서 루프백 주소에서만 연결을 받습니다. 중계는 이 기계의
`127.0.0.1`에서만 연결을 받고, 연결마다 `docker exec`로 컨테이너 안의 `127.0.0.1:8765`에 잇습니다. 컨테이너에 포트를
공개하면 같은 Docker 망의 데모 노드도 로그인 없는 화면에 바로 닿으므로 그렇게 하지 않습니다.

처음 띄울 때 컨테이너 안에 작업 폴더 `/work/ui`를 만들고, 데모가 이미 가진 것을 실제 운영자가 넣는 자리에 둡니다.

| 넣는 것 | 쓰는 화면 |
|---|---|
| `extend.sh`가 만든 선언 | 01 관측의 「대상 노드와 기대 상태」 |
| 상류 적재에 준 자산 스코프 정책(`scope-assets.csv`) | 02 · 03. 같은 정책이어야 스냅샷 지문이 상류 이력과 맞습니다 |
| 노드 접근 정보(`hosts.csv`)와, 준비 도구로 받아 확인한 상류 공식 수집기 | 01 관측 실행 |
| 지금까지의 관측 결과 | 02 대조. 01에서 다시 관측하면 화면이 새 결과로 바꿉니다 |
| 승인 서명 키(작업 폴더 밖, `/work/ui-approval.key`) | 04 프로비저닝 |

자산 스코프 화면은 「아직 계층이 없습니다」로 열립니다. 편집할 계층은 비어 있지만, 02 · 03이 쓰는 자산 스코프 정책
(`scope-assets.csv`)은 상류 적재에 쓴 것을 그대로 넣어 두었기 때문입니다. 자산 스코프 화면에서 계층을 만들어 확정하면 새 정책은
`asset-scope.csv`로 나가며, 데모가 이미 쓰는 `scope-assets.csv`를 자동으로 바꾸지는 않습니다. 화면을 다시 띄워도
02 · 03은 `scope-assets.csv`를 그대로 씁니다. 확정한 정책을 대조에 쓰려면 아래 「새 정책 활성화」를 따릅니다.

**데모의 수집기는 상류 공식 릴리스 자산뿐입니다.** 준비 도구(`go run ./inventory/cmd/pqcaton-collectors fetch`)가 go.mod가 고정한 판의 자산을
받아, 출처 증명(저장소 · 서명 워크플로 · 태그 고정) · `SHA256SUMS` · 안전한 압축 풀기 · release manifest의 파일마다 해시 · 판 ·
커밋 · 꺼낸 실행 파일의 출처 증명 · 예상한 파일만을 확인한 뒤 한 번에 옮깁니다. 대상이 이미 있으면 덮어쓰지 않습니다. `ui.sh`는
아무것도 내려받지 않고, 화면을 띄울 때마다 그 폴더를 다시 확인한 뒤에만 작업 폴더의 `collectors`로 바꿔 넣습니다. 확인하지
못하면 아무것도 바꾸지 않고 멈춥니다. 준비 폴더의 대상(OS · 아키텍처)이 `pqcota-ctl` 컨테이너와 다르면 확인하기 전에 거절합니다.
바꿔 넣을 때는 작업 폴더 안의 임시 자리에 복사해 해시를 다시 본 뒤 `rename`으로 들이고, 실패하면 기존 `collectors`를
되돌립니다. 01은 수집기와 `collector.jar`를 모두 「확인됨」으로 보이고, 화면은
`-allow-unverified-collectors` 없이 뜹니다([운영자 안내서 2절](../docs/operator-guide.ko.md#2-설치)의 「수집기의 판」). 상류 소스로
빌드한 수집기로 데모를 돌리는 길은 두지 않습니다. 폴더 자리는 `PQCATON_COLLECTORS`로 바꿀 수 있습니다.

작업 폴더는 처음 한 번만 채웁니다. 그 뒤로는 화면에서 한 일이 그대로 남고, `ui.sh stop`도 폴더는 지우지 않습니다.
`down.sh`로 환경을 내리면 컨테이너와 함께 없어집니다. `Ctrl+C`는 중계만 닫으므로, 화면은 `ui.sh`를 다시 실행하면
그대로 이어서 볼 수 있습니다. 이 기계에서 다른 `pqcaton-ui`를 이미 8765로 띄웠다면 `PQCATON_UI_PORT=8766`처럼 다른
포트를 줍니다. 빌드에는 `extend.sh`와 같이 Go가 필요하고, 중계에는 python3가 필요합니다. Go가 없으면 linux용
`pqcaton-ui` · `pqcaton-collectors`를 `PQCATON_BIN_DIR`로 주고, 이 기계용 `pqcaton-collectors`를 `PATH`에 둡니다.

`extend.sh`는 새 컨테이너를 만들지 않습니다. 실행 중인 `pqcota-ctl`에 이 리포의 `pqcaton-report`를 주입하고,
core가 이미 수집한 `/work/results`에 **선언(declaration.json)**을 대조해 3-상태 인벤토리 + 거버넌스
토폴로지를 만들고, **그 결과를 판정해 계획을 만든 뒤, 상류의 승인 → 생성 → 적용 → 되돌림까지
실제로 돌립니다.**

**대조에서 멈추지 않습니다.** 관측 → 대조 → 판정 → 승인 → 생성 → 적용 → 되돌림이 한 바퀴로
이어집니다. 그 사이가 끊겨 있으면 데모에서 드러나야 합니다. 실제로 두 번 그랬습니다. v0.9.0 전에는
데모가 대조에서 멈춰 아무도 몰랐고, v0.16.0은 조치 종류를 고르지 않은 항목이 확정을 막게 됐는데
데모가 고르지 않아 `close`에서 끊긴 채 릴리스에 나갔습니다. 그리고 그 끊긴 데모를 다시 돌려서야
JVM 수집기의 결과 파일(`*.jsonl`)을 이 리포가 읽지 않고 있었다는 것이 드러났습니다.

**판정한 사람과 실행을 승인하는 사람이 다릅니다.** `pqcaton-decide close`가 내는 `/work/plan.json`은
`IN_REVIEW`이고 승인 칸이 비어 있습니다. 데모는 거버넌스 쪽 승인자(`governance-1`)가 자기 키를
만들어 등록하고 `pqcota-approve`로 `FINALIZED`로 올리는 것까지 보입니다. 판정자 표시(「데모 판정자」)는
판정 원장에 남고, 실행 승인 서명은 상류가 등록된 키로 검증합니다. 계획 id가 세션 id를 담으므로
`/work/judgments.jsonl`에서 그 세션의 판정을 되짚을 수 있습니다.

Go가 없는 호스트에서는 `PQCATON_BIN_DIR=<dir>`로 미리 빌드한 `pqcaton-report`·`pqcaton-decide`를 줍니다.

**되짚기 사슬을 재는 전용 픽스처**가 따로 있습니다. `PQCATON_E2E_TRACE=1`을 주면 선언에서 자산을
전부 빼서, 정책이 관리 대상으로 남긴 관측이 모두 UNDECLARED가 됩니다. 그래야 **이 리포가 만든 계획으로**
승인 → 생성 → 레코드 → 실제 스냅샷 id까지 사슬이 한 바퀴 돕니다. **데모 서사가 아니라 검증용입니다.**
없는 자산을 지어내는 대신 선언만 비우며, 이는 선언을 아직 작성하지 않은 조직에서 실제로 생길 수
있는 상태입니다. 기본 실행은 현실적인 선언 그대로 돌아, 정책이 관리 대상에서 뺀 자산에는 조치를
세우지 않는다는 것을 보입니다.

### 새 정책 활성화

자산 스코프 화면에서 확정한 정책을 대조에 쓰려면, pqcota를 그 정책으로 다시 적재한 뒤 01 관측에서 활성화합니다. 데모는 재적재를 한 명령으로
합니다. 화면이 떠 있어도 됩니다(재적재는 작업 폴더를 건드리지 않습니다).

```bash
./demo/scripts/ui.sh apply-scope
```

`apply-scope`는 작업 폴더의 파일(자산 스코프 화면에서 확정한 정책 · 선언 · 결과), `pqcota-ingest`, pqcota DB를 점검한 뒤, 화면이 쓰는
`/work/ui/results`와 자산 스코프 화면에서 확정한 정책으로 pqcota를 다시 적재합니다. **활성화는 하지 않습니다.**

활성화는 화면 01 관측의 「활성화할 확정 정책: 재적재와 활성화」에서 합니다. 「정책 활성화 확인」을 누르면 화면이 pqcota 이력에서 노드마다 최신 적재 결과가 새 정책으로
만든 결과와 같은지 대조하고, 일치하면 확인 페이지에 「확인 시점에 pqcota 이력과 일치했습니다」를 보입니다. 활성화를 누르면
처음부터 다시 대조한 뒤 활성화합니다. 하나라도 없거나 다르거나 조회할 수 없으면 아무것도 쓰지 않습니다. 과거 실행에 같은
지문이 있었다는 것만으로는 통과하지 않습니다. 데모의 화면은 `ui.sh`가 읽기 전용 역할(`pqcaton_ui`)의 `PQCOTA_DSN`을 넘겨
띄웁니다. 화면은 pqcota 이력 없이 시작하지 않습니다.

활성화하면 03이 새 정책으로 다시 세운 새 회차로 열리고, 지난 결론은 「지난 정책 결론」으로만 보입니다. 활성화 전에
확정한 계획은 04에서 서명 · 생성되지 않습니다.

**이력은 세 역할로 나눕니다.** 상류 데모는 관리자 계정(`postgres`)으로 적재하므로 그 계정이 표를 소유합니다. `extend.sh`는
맨 앞(0/8)에서 이 이력을 이미 쓰던 설치로 보고, 운영자 안내서 9절 「기존 이력을 세 역할로 옮기기」를 그대로 밟습니다.

| 역할 | 데모에서 하는 일 |
|---|---|
| `pqcota_schema` | 표를 소유하고 `pqcota-inventory -init-schema` · `pqcota-records -init-schema`를 돌립니다 |
| `pqcota_ingest` | 판정 조직 적재, `ui.sh apply-scope`의 재적재, `extend.sh`의 생성 기록(`pqcota-provision --dsn`)을 `PQCOTA_AUTO_DDL=0`으로 합니다 |
| `pqcaton_ui` | 화면이 이력을 읽고, 명령(`pqcaton-decide`)이 대조합니다. 모든 표에 읽기 권한만 있습니다 |

`extend.sh`는 표가 모두 `pqcota_schema`의 것인지, `pqcota_ingest`가 표를 만들 수 없는지, `pqcaton_ui`가 어느 표에도 쓸 수 없는지를
확인합니다. `pqcota_ingest`가 `PQCOTA_AUTO_DDL=0` 없이 적재하면 거절된다는 것도 확인합니다. 비밀번호는 실행마다 새로 만들어
`pqcota-ctl`의 `~/.pgpass`(0600)에만 두므로 연결 정보에는 비밀이 없습니다.

**적재는 두 조직에 갑니다.** 상류 데모의 `demo.sh`는 기본 조직에 적재하고, 그 적재는 `extend.sh`의 생성 단계(`pqcota-provision`)가
씁니다. 화면과 명령은 판정 조직(`demo-corp`)의 pqcota 이력만 대조하므로, `extend.sh`가 같은 결과 · 같은 정책을 판정 조직에도
적재해 둡니다. 정책을 바꿀 때 `ui.sh apply-scope`가 다시 적재하는 곳도 판정 조직입니다.

### 종단 검증

`make e2e-demo`가 이 데모를 처음부터 띄워 정책 활성화를 화면과 명령 두 길로 끝까지 돌리고 실패 경로까지 잽니다(IC-U152). 상류 다섯 리포를
v0.20.0으로 나란히 받아 두고 `PQCOTA_DIR`로 상류 `pqcota` 체크아웃을 줍니다. `<…>`를 실제 경로로 바꾼 뒤 실행하십시오.

```bash
PQCOTA_DIR='<상류 pqcota 체크아웃 경로>' make e2e-demo
```

상류 데모는 컨테이너 · 네트워크에 고정 이름(`pqcota-ctl` 등)을 씁니다. 그래서 이 검증은 실행마다 `pqcaton-e2e-…`라는
dind 컨테이너를 따로 띄우고, 상류 데모를 그 안의 Docker 데몬에 띄웁니다. 같은 호스트에서 pqcota 쪽이 데모를 띄워 쓰고
있어도 이름이 부딪히지 않고, 그 데모를 건드리지도 않습니다. 끝나면 실패했더라도 그 dind 컨테이너와 볼륨을 지웁니다.
dind 안의 데몬은 `docker exec`로 띄운 프로세스에 umask 0000을 물려주므로, 안쪽 실행에서는 그 umask를 호스트와 같은 022로
맞춥니다. 파일 권한 검사를 끄는 것이 아닙니다.
안쪽 데몬은 베이스 이미지를 처음부터 받으므로 첫 빌드가 오래 걸립니다. 호스트에 `docker:dind` 이미지가 있어야 하고, 필요한
프로그램이나 `PQCOTA_DIR`이 없을 때도 건너뛰지 않고 실패합니다.

우분투 기본 미러가 느린 곳에서는 `E2E_UBUNTU_MIRROR=<미러 이름>`(예: `kr.archive.ubuntu.com`)을 함께 줍니다. 그러면 dind 안의
빌드만 `archive.ubuntu.com` · `security.ubuntu.com`을 그 미러의 주소로 풉니다. 상류 Dockerfile은 고치지 않고, apt의 서명
검증도 그대로입니다.

`E2E_KEEP_WS=<폴더>`를 함께 주면 정리 전에(실패했더라도) 작업 폴더를 그 폴더로 꺼내 둡니다. 꺼낸 폴더는 컨테이너가 지워진 뒤에도
남으므로, 옛 판이 새 형식 처리 기록 앞에서 멈추는지 보는 시험에 그대로 쓸 수 있습니다.

## 요구 사항
- **pqcota 리포 체크아웃**: 선언을 그쪽 `topology.yaml`에서 만듭니다. 형제 디렉터리
  (`../pqcota`)에 두거나 `PQCOTA_DIR=/경로`로 알려 줍니다.
- **pqcota는 v0.20.0으로 받습니다.** 상류 데모는 다섯 리포를 나란히 받아 한 이미지로 묶으므로, 다섯 리포를
  모두 같은 태그로 이 리포 옆에 받습니다. 다른 판을 받으면 상류가 다른 규칙 묶음으로 이력을 쌓아, 이 리포가
  만든 계획의 근거를 상류 이력에서 찾지 못할 수 있습니다. pqcaton 판마다 함께 쓰는 판은
  [판별 표](../docs/compatibility.ko.md)에 있습니다.

  ```bash
  for r in pqcota pqcota-common pqcota-inventory pqcota-discovery pqcota-provisioning; do git clone --branch v0.20.0 https://github.com/randyinthedev-hash/$r; done
  ```
- 실행 중인 pqcota 디스커버리 데모(위 1단계).
- 이 기계의 **Docker**: 상류 데모가 노드 · 제어 컨테이너 · 데이터베이스를 Docker로 띄웁니다.
- 공식 수집기를 받는 데(위 3단계) **`gh`**(GitHub CLI 2.49 이상, `gh auth login`으로 로그인)와 GitHub에 닿는 망.
- 빌드 기계에는 **Go**와 **python3**만 있으면 됩니다. pqcota v0.5.0부터 모듈 경로가 리포 주소와 같아져
  `go build`가 계약을 스스로 받아옵니다. 형제 체크아웃도 `replace`도 필요 없습니다.
- **Graphviz(`dot`)는 이 기계에 없어도 됩니다.** 토폴로지 SVG는 `pqcota-ctl` 컨테이너 안에서
  그립니다. 없으면 DOT 원문만 회수하고 나머지는 그대로 됩니다
  ([사전 준비](../README.ko.md)).
